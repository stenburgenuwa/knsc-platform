Kenya National Sub County League — Platform Architecture

Software Architecture & Implementation Roadmap

This document specifies the architecture for the KNSCL Platform prior to implementation, per the project's database-first, API-first, and clean-architecture mandates. The Kilifi County pilot is the first deployment, not the design boundary: every entity below scopes through county → league → season so additional counties, competitions and federations attach without schema changes.

1. Layered Architecture

Responsibilities stay strictly separated. Each layer depends only on the one below it, never the reverse.

Presentation Mobile-first web UI (public site + role dashboards) ↓ Business Logic Feature use-cases, validation, workflow rules ↓ Services Standings calc, notifications, media, auth ↓ Repositories Typed data-access layer (one per entity) ↓ Database PostgreSQL, county/league-scoped throughout

The frontend never queries the database or embeds business rules — it calls versioned REST/GraphQL endpoints and renders their responses. Every write passes through a repository, never raw SQL from a controller.

League standings and top-scorer lists are not stored — they are derived views computed by the Standings service from match_reports and match_events, so re-running a season's calculation is always safe.

9. Recommendations Before Development Begins

A few refinements to the brief worth deciding now rather than mid-build:

Multi-tenancy by construction. Every table above carries a path back to county → league → season. Enforce this scope in the PermissionService, not per-page, so a League Manager literally cannot query another league's data.

Standings as derived data. Never let editors hand-edit a league table — store match reports and events, compute the table. This also makes corrections (an overturned result) safe and auditable.

Offline-tolerant team sheets. Team managers and referees will often be at a pitch with poor signal. Team-sheet and match-report forms should queue submissions locally and sync when connectivity returns.

SMS as a swappable provider. Wrap the SMS gateway behind NotificationService so a Kenyan aggregator (e.g. Africa's Talking) can be swapped without touching calling code.

Seed data stays generic. Database seeders should generate a fictional county/league/clubs by default; Kilifi's real clubs and fixtures load as a separate, explicitly-loaded pilot dataset.
